No Ingress is created. To try Pinwall from this machine, install with

  kubectl --namespace {{ .Release.Namespace }} port-forward service/{{ include "pinwall.fullname" . }} 8080:{{ .Values.service.port }}

On its first start Pinwall prints a one-time link in its log that creates the owner account:
  kubectl --namespace {{ .Release.Namespace }} logs deployment/{{ include "pinwall.fullname" . }}

{{- end }}
{{- if not .Values.existingSecret }}

No existingSecret is set, so Pinwall uses SQLite in /data and generates its secret key there.
For PostgreSQL, set PINWALL_DATABASE_URL and PINWALL_SECRET_KEY (and the S3 keys, if you use S3)
through existingSecret and secretFiles; they are never accepted in env.
{{- end }}
