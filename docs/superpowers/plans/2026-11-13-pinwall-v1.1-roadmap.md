# Pinwall v1.1 (personal spaces) Implementation Plan — Roadmap

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Pinwall 1.1.0. Each person gets a private space, the operator controls who may create
public share links, and quotas, rate limits and admin moderation make open sign-up safe. An
installation that does not opt in keeps behaving exactly like 1.0.

**Architecture:**
- **Ownership.** A project gets an owner. Every content-domain function that finds or lists content
  takes a `Scope`, so the TypeScript compiler finds every caller that must say whose view it is.
  `team` mode passes everything through. `personal` mode adds one SQL predicate:
  `projects.owner_id = viewer`.
- **Defense in depth.** Content grants, live streams and publish commits check the predicate again
  at use.
- **Quotas, rate limits and admin moderation** sit on top of the same predicate and the existing
  revoke machinery.

**Tech Stack:** unchanged from 1.0. Read the roadmap `2026-11-10-pinwall-roadmap.md`. No new
dependency is expected; if one is needed, it must pass the 1.0 license rules.

**Spec:** `docs/superpowers/specs/2026-11-13-pinwall-personal-spaces-design.md`, which builds on
`docs/superpowers/specs/2026-11-10-pinwall-design.md`. Read both.

**Status:** draft. The milestones below assume the recommended answers to D1–D8 (spec §12). Owner
answers that differ change the milestones noted in §"If the owner decides otherwise".

**How this plan is organized:** as for 1.0.
- This roadmap fixes the shared names, configuration, data model, routes, the access inventory and
  the milestones.
- Each milestone gets a task-level plan, `docs/superpowers/plans/2026-11-13-pinwall-mN-<name>.md`.
  An Opus planner writes it against the real code, following `.superpowers/sdd/planner-common.md`,
  once the owner has approved the spec and the milestones it depends on are merged.
- A milestone plan may refine anything here. If it changes a shared name, it updates this file in
  the same commit.

## Global Constraints

- **Everything in the 1.0 roadmap's Global Constraints still applies**, word for word. In
  particular:
  - original work only;
  - license rules;
  - Conventional Commits with the `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
    trailer;
  - English UI through i18n;
  - `Cache-Control: no-transform` on content;
  - browser errors as HTML pages.
- **`PINWALL_VISIBILITY` defaults to `team`.** With the default, every 1.0 test passes unchanged,
  and every API response, MCP result and event has the 1.0 shape and content. New DTO fields are
  additive only.
- **An id from another space answers exactly like a missing id:** `404 not_found` on REST, the same
  MCP error text, and the same HTML page. Never 403. The visibility predicate goes inside the lookup
  query, never as "fetch, then compare owner".
- **`SYSTEM_SCOPE`** (unscoped access) may be imported only by an allow-list:
  - share-link resolution (`domain/share-access.ts`);
  - deletion and blob GC;
  - backup and restore;
  - transfer and purge;
  - the admin moderation routes;
  - startup.

  `apps/server/test/spaces/scope-guard.test.ts` enforces the allow-list.
- **The IDOR suite runs in both modes in CI.** It is the release gate.
- **Run at most 2 implementer agents at once**, with `VITEST_MAX_WORKERS=2` on full runs. The
  machine is shared.
- **Work happens on branch `v1.1`**, cut from `main` at the commit that adds this roadmap, with git
  worktrees for parallel milestones. Nothing is pushed or released until the owner says so.
- **Nothing on the homelab cluster changes from this work** until the rollout step in M13. Even then
  the Pinwall session first messages the homelab session (`k8s-homelab-9e`), which owns
  `infra/argocd/apps/pinwall.yaml` and the Zitadel config.

## Review Focus

These are the failure modes the spec implies but no acceptance item names. Each has its test in the
milestone that owns it.

1. **Search crowding.** Person A has 1,200 artifacts that match "report" and person B has one.
   - **Expected:** B's search returns B's one artifact on the first page.
   - **Expected:** A's matches neither push B's out of the 1,000-hit window nor change B's ranking.
   - **Owner:** M10 (filter inside `searchQuery`).
2. **Transfer while the old owner has the artifact open.**
   - **Expected:** their live stream closes within one `SSE_HEARTBEAT_MS` (25 000 ms).
   - **Expected:** their review grant answers 410 on the next request, and Recent no longer lists the
     artifact.
   - **Owner:** M11 (transfer), on M10's checks.
3. **Two publishes at the quota edge at the same time.** Each fits alone; together they go over.
   - **Expected:** exactly one commits. The other gets `quota_exceeded` and leaves no version and no
     orphaned blob.
   - **Owner:** M11 (quota check under `lockUser` in the commit transaction).
4. **A list cursor or upload URL made before a mode switch or a transfer.**
   - A paging cursor minted in `team` mode, used after a restart in `personal` mode, returns only
     visible items.
   - An upload URL minted before its artifact was transferred is refused at commit, with no version.
   - **Owner:** M10 (cursor), M11 (upload URL).
5. **`--to <email>` matches more than one user.** On the owner's instance, the local Owner and the
   OIDC account may share an email.
   - **Expected:** `pinwall transfer` refuses, lists the matching user ids, and moves nothing.
   - **Owner:** M11.

## Shared names (new in 1.1)

**`Config`:**
- `visibility: 'team' | 'personal'`
- `shareLinks: 'members' | 'approved'`
- `quota: { bytes: number; artifacts: number }`, where `0` means no limit

These are read in `config/load.ts` and described in `config/catalog.ts`. The catalog gets a new
section `spaces` with the title "Spaces and sharing". The quota variables go in `limits`.

**`apps/server/src/domain/spaces.ts`** (M10) holds the scope types, the predicate helpers, the
transfer and the default-project helpers:

```ts
export type Scope =
  | { kind: 'viewer'; user: UserRow; visibility: Visibility; admin: boolean }
  | { kind: 'system' };
export const SYSTEM_SCOPE: Scope;
export function scopeOf(c: Context<AppEnv>): Scope;              // from authOf(c) + config
export function scopeForUser(deps: AppDeps, user: UserRow): Scope; // upload URLs, MCP, SSE
/** Adds the space predicate to a query that has `projects` joined (team/system: no-op). */
export function whereVisible<QB>(qb: QB, scope: Scope, projectIdColumn: string): QB;
export function canManageProject(scope: Scope, project: ProjectRow): boolean;
export async function defaultProjectFor(deps: AppDeps, scope: Scope): Promise<ProjectRow>;
export async function transferContent(deps: AppDeps, fromUserId: string, toUserId: string):
  Promise<{ projects: number; artifacts: number }>;               // M11
```

**Domain signatures** (M10). Each of these gains `scope: Scope` as the parameter after `deps` or
`db`. Callers in `api/`, `mcp/` and `content/raw-links.ts` pass `scopeOf(c)` or
`scopeForUser(...)`.
- `getArtifact`, `listArtifacts`, `listRecent`, `getProject`, `listProjects`, `createProject`,
  `updateProject`
- `listVersions`, `getVersionByNumber`, `getCurrentVersion`, `listVersionFiles`
- `checkTarget`, `commitVersion`, `restoreVersion`
- `deleteArtifact`, `deleteVersion`
- `listThreads`, `createThread`, `addReply`, `editComment`, `deleteComment`, `resolveThread`,
  `reopenThread`
- `createShareLink`, `listShareLinks`, `revokeShareLink`
- `diffVersionFiles`, `diffTextFile`, `diffMarkdownFile`
- `updateArtifact`

In `team` mode they behave as in 1.0. `canDelete`, `canDeleteComment` and `canRevoke` take the
`Scope`. In `personal` mode the space owner may do everything to their own content (spec §4.3).

**`searchQuery(db, dialect, text, limit, scope)`** joins `artifacts` and `projects` and applies the
predicate before `LIMIT`. Both the SQLite FTS5 query and the Postgres `tsvector` query do this.

**DTOs** (`@pinwall/shared`; additive only):
- `ArtifactSummary.can_manage: boolean`. It is computed on the server and replaces the SPA's
  `admin || created_by === me` rule.
- `Project.owner: { id, name } | null`.
- `PublicConfig.visibility` and `PublicConfig.share_links`.
- `Me.can_create_share_links: boolean`.
- `Me.usage: { bytes, artifacts }` and `Me.limits: { bytes: number | null; artifacts: number |
  null }`. `null` means no limit.
- Admin DTOs: see Routes.

**Errors:**
- A new `ErrorCode` `quota_exceeded` (HTTP 413) with `details: { used_bytes, limit_bytes,
  needed_bytes }` or `{ used_artifacts, limit_artifacts }`.
- Refusing a share link because of policy uses `forbidden` with `details.reason =
  'share_links_not_approved'`.

**Rate rules** (`RATE_RULES`, keyed by user id):
- `publish`: 60 per 600 000 ms. It replaces `PUBLISH_SESSION_RATE` and counts sessions, inline
  publishes, web uploads and restores.
- `grant`: 600 per 3 600 000 ms. It counts preview, raw-link and review grants.
- `shareLinkCreate`: 30 per 3 600 000 ms.
- `projectCreate`: 30 per 3 600 000 ms.

**CLI** (`main.ts`):
- `pinwall transfer --from <id|email> --to <id|email>`
- `pinwall visibility team --confirm`

## Data model: migration `0003_spaces`

| Change | Detail |
| --- | --- |
| `projects.owner_id` | `text NULL REFERENCES users(id)`. Index `projects_owner_id_idx`. Partial unique index `projects_owner_default_idx` on `(owner_id) WHERE is_default = 1`. |
| `users.share_approved` | `integer NOT NULL DEFAULT 0` |
| `users.quota_bytes` | `bigint` (Postgres) / `integer` (SQLite), `NULL` |
| `users.quota_artifacts` | `integer NULL` |
| `instance_settings` | `key text PK, value text NOT NULL, updated_at bigint NOT NULL`. Holds `visibility.last`. |
| Backfill | `backfillProjectOwners(db)`, exported from `db/migrations/0003_spaces.ts`. Sets `owner_id = created_by`. For a NULL creator, uses the first of: the owner account (`kind='owner'`); the earliest active admin (`role_override='admin'`, or `idp_role='admin'` with no override); the earliest user. With no users, it stays NULL. |

**Backup:**
- `instance_settings` joins `BACKUP_TABLES` (after `users`), `TABLE_KEYS` and `NOUNS`.
- New columns ride along through `select *`.
- `restore` calls `backfillProjectOwners` after loading the rows, so a 1.0 archive ends up as if it
  had been migrated.

**Usage:** `usageOf(db, config, userId)` lives in `domain/usage.ts` (M11).
- In `personal` mode it sums `versions.total_bytes` joined through `artifacts` to `projects` where
  `owner_id = ?`.
- In `team` mode it sums over versions where `versions.created_by = ?`, and counts artifacts by
  `artifacts.created_by`.
- Existing indexes cover both.
